Two changes from the drawing: the popup shows each server’s models under its name but not their sizes (a Mac menu can’t line them up on the right), and the opening state is a line of words with no bar. When nothing answers, Another address sits under Look again or Open Ollama, so a server elsewhere can still be found.

Asked 12 Nov 2026: “Currently, the only key we allow SigmaFlow to use is the Anthropic key. What if somebody wants to use their locally run models as the brain instead?” Yes. Ollama and LM Studio both answer at an address on the Mac, in the same language the OpenRouter choice already speaks. So a fourth engine can sit beside Apple Intelligence, Claude and OpenRouter, run custom styles and Autowrite, and need no key and no account. Text never leaves the Mac.

Already decided: SigmaFlow finds Ollama (port 11434) and LM Studio (port 1234) by itself, lists their models, and has an address for any other server of the same kind (llama.cpp, Jan, MLX). Dictation cleanup, meeting titles and search stay as they are.

This page is only about how it looks. Five questions, from where the choice sits to what Autowrite sends it. The example Mac has Ollama with three models; this Mac really has Ollama with gemma4:e4b, which is what it will be tested on.

Elsewhere. Editors that run local models, Zed and Raycast among them, name the server, list the models it already has, and keep the address somewhere you rarely touch.

    1. Where it sits in the chooser

    1AA fourth row, Your own modelMY PICK

    The chooser on Custom styles grows by one row, under OpenRouter. Picked, it opens like a key row does, with the model in place of the key. Same card, same rule: one look for every engine.

    1BTwo groups: on this Mac, and with your key

    The four rows split under two small headings, so “never leaves the Mac” is said once, by where the row sits. Clearer about privacy; one more thing on a card that is otherwise a plain list.

    1CA row per server SigmaFlow finds

    Ollama and LM Studio each get their own row, by name, once they are on the Mac; a server that is installed but not open is faint. Another server is the last row. Says exactly what it found; the list changes from Mac to Mac.

    2. What the row opens to

    2AThe model, and where it was foundMY PICK

    A popup of every model SigmaFlow found, already set to the first one, and Use this model. Under it, faint, the server it came from and Change, which turns that line into an address field. The popup lists each server’s models under its name (right).

    2BAddress and model, side by side

    Two fields, as Zed does it: the address, already filled in, and the model. Everything in view; the address is the part almost nobody changes.

    2CThe models as a list

    Every model as its own line with its size, pick one. Easier to compare at a glance; the card grows with every model you download.

    3. When nothing is open

    3ASay so, and Look again

    “Open Ollama or LM Studio, then look again.” One button. The same words whether a server is installed or not.

    3BOpen Ollama for youMY PICK

    When Ollama or LM Studio is on the Mac but closed (this Mac today), the row offers to open it. SigmaFlow opens the app, waits for it to answer, and the row becomes 2A. With neither installed, it reads like 3A, with Look again. The same happens later: a rewrite or Autowrite with the server closed opens it first, then writes.

    3CNo row until a server answers

    The row appears only once Ollama or LM Studio is running. Nothing to explain; nobody who hasn’t set one up ever learns it is possible.

    4. What it says once picked

    4AThe model, by nameMY PICK

    “Rewrites run on gemma4:e4b”, with “In Ollama, on this Mac. Your text never leaves it.” under it. Autowrite’s AI model row says the same name. The person chose the model, so its name is the useful part; Change engine reopens the chooser.

    4BYour own model, the name underneath

    “Rewrites run on your own model”, with the model and server in the caption. Matches the row’s name; one step further from what is actually running.

    5. What Autowrite gives it

    5AThe screen’s wordsMY PICK

    As OpenRouter gets today: the words SigmaFlow read off the screen, or the page’s words in a browser with the extension. Nothing to draw; Autowrite looks the same. A small model on a laptop answers in a few seconds this way.

    5BThe screenshot too, when the model can see

    As Claude gets today. Ollama says which of its models can see pictures; those get the screenshot beside the words, the rest get words only. Better on screens that are mostly pictures; a picture can add many seconds on a laptop before the first word appears.

    How it would work underneath

    1. One more engine, StyleEngineChoice.local, through the same CloudTextClient as OpenRouter: /v1/chat/completions, streamed for Autowrite. No key, nothing in the Keychain, so no Keychain question after an update either.
    2. Finding servers: GET /v1/models on localhost:11434 and localhost:1234 when the chooser opens, half a second each. The address and the model are settings, exported with the others.
    3. Opening Ollama (3B) is open -a Ollama (or LM Studio’s lms server start), then asking every half second for up to 20 seconds.
    4. Slower first answer. A local model loads into memory on its first request, which can take 10 to 30 seconds before anything comes back. Local rewrites get 90 seconds in place of 30, so a cold start doesn’t fail; Autowrite’s overlay shows its waiting state meanwhile, as it does now.
    5. Failures read like the others: “Ollama isn’t open.” or “Ollama doesn’t have gemma4:e4b any more.”, and the text is left alone.
    Also possible, not on this page: SigmaFlow already downloads its own Gemma 4 (for picture search and Tamil titles). That model could be an engine too, with no Ollama at all. It is smaller than most people’s Ollama models, and holds 4 GB while it writes. A separate ask if wanted.
