Updating SigmaFlow from inside the app

Picks, 12 Nov 2026: 10 + 02. Built in 1.1.0. The downloading line under the version (02, left) was left out: Sparkle downloads with no progress to show. The notice's What's new opens the GitHub release, and the release was named 1.1.0, not 1.0.2.

Asked 12 Nov 2026: "Can the people already using SigmaFlow get an update right from their Mac, once I push it to GitHub and release it? There's this framework called Sparkle." Yes. Sparkle is how most Mac apps outside the App Store do this (VLC, iTerm, Rectangle, Raycast before it moved). You publish a release on GitHub as today; every copy of SigmaFlow checks a small list of versions once a day, downloads the new one, checks it really came from you, swaps itself and opens again. Nothing to drag to Applications, no Gatekeeper right-click.

This page is only about how it looks. Ten ways for SigmaFlow to tell someone a new version is ready, from loudest to quietest. Each one uses the same update underneath, so they can be mixed. The example release is 1.0.2 with what has really landed since 1.0.1: filmed meetings, where a call was, and the dictionary in the overlay.

Reply with one number, or two that work together, for example "10 + 02". My pick is marked: install quietly when SigmaFlow quits (10), with the sidebar's version line saying so when one is waiting (02). It never interrupts a dictation and asks nothing.

Mobbin has no Mac apps, so the Mac-only places (menu bar, above the Dock, Sparkle's own window) are drawn from macOS itself.

Whatever is picked: SigmaFlow never restarts while you are dictating, recording a meeting, taking notes or writing with Autowrite, and never while a transcript is being made. Restart now waits for that to finish. Everything you have open (the page, the tab) comes back as it was.

    Loud: it asks

    01Sparkle's own window

    What Sparkle shows with no design work: a Mac window with the release notes, Skip This Version, Remind Me Later and Install Update, and a box to install future ones by themselves. It looks like every other Mac app's updater, not like SigmaFlow. Its sentence is reworded here; Sparkle's own has an em dash in it.

    03A card above the Dock, like Record this meeting?

    The call card's twin, in the same place: SigmaFlow's icon, "SigmaFlow 1.0.2 is ready", Restart now and When I quit. The line along its foot runs down over 20 seconds and the card goes; unanswered counts as When I quit. Two buttons, no third to close it.

    07A card in the window, picture and list

    Lovable's split card, opened over the page the next time the window comes to the front. Left, the new thing moving (a README picture, which the app already draws itself). Right, three lines, each a verb and what you get. Restart to update and Later.

    08What's new, as a sheet you scroll

    Gumloop and Discord: version and date at the top, one short section per change, a picture where it helps, Later and Restart to update at the foot. More room than 07; easier to skip.

    Middle: it shows, you choose when

    04A strip across the top of the page

    One line over whatever page is open: "SigmaFlow 1.0.2 is ready." with Restart and What's new. It stays until you restart, on every page, which is the cost.

    05A dot on the menu bar icon

    A small dot on SigmaFlow's menu bar Σ, and "Restart to update to 1.0.2" at the top of its menu. Works when the main window is closed, which is most of the day.

    09What's new, a page of its own

    The version line at the sidebar's foot becomes What's new. Its page lists every release, newest first, the way Transcriptions lists days. The newest, when it is waiting, has Restart to update beside it. The release notes come from the GitHub release.

    06Updates in Settings

    Tailscale's switch: in Settings, Your data, three rows under the SigmaFlow folder card. The version you have, Install updates by themselves (on by default), and Check now. When one is waiting, the first row says so and has Restart.

    Quiet: it just happens

    02The sidebar's version lineMY PICK, WITH 10

    The 1.0.1 at the foot of the sidebar is where people already look for the version. While a new one downloads, a thin line fills under it. Once it is ready: "1.0.2 is ready" and Restart, in the same faint ink as the path bar. Nothing anywhere else.

    10Installed when SigmaFlow quitsMY PICK

    No question at all. The new version downloads in the background and is put in place the next time SigmaFlow quits or the Mac restarts. If it has not quit in three days, SigmaFlow restarts itself at a quiet moment (nothing recording, no key pressed for ten minutes). When it opens again, a small notice above the Dock, where the learned-rule notice shows, says UPDATED and 1.0.2 with What's new for five seconds.

    How it would work underneath

    The pieces.
    1. Sparkle 2 added through SwiftPM. Its framework goes into Contents/Frameworks and is signed before the app, like the MCP helper today.
    2. A signing key pair made once with Sparkle's generate_keys. The private half stays in your Mac's Keychain; the public half goes into Info.plist as SUPublicEDKey. SigmaFlow refuses any download that is not signed by that key, so nobody can push a fake update even if the GitHub account or the download is tampered with.
    3. A list of versions, appcast.xml, kept in the repo and read from GitHub (SUFeedURL). Each entry is a version, its notes and the DMG's address under Releases.
    4. make release: builds the DMG as make dmg does, signs it with Sparkle's sign_update, adds the entry to appcast.xml, makes the GitHub release with gh and pushes. One command per release.
    Three things to know.
    • Everyone on 1.0.0 or 1.0.1 downloads once more by hand. Those copies have no updater in them. From the first Sparkle version on, it is automatic.
    • Permissions survive updates, as long as every release is signed with "SigmaFlow Dev" from your Mac. Accessibility and the microphone are tied to that certificate (checked today: the installed app's requirement is that certificate's fingerprint). If that certificate were ever lost and a release signed with another, every user would silently lose the hotkeys. Back it up.
    • The Keychain password question still comes after each update for people who saved a Claude or OpenRouter key. That is the self-signed certificate, already waiting on the Developer ID; the Developer ID would also let releases be notarized.
